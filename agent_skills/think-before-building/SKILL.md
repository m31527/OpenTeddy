# 動手前先想（做東西、修東西都一樣）

## 1. 先寫下「做好了」長什麼樣
用一句話寫出：使用者拿到後會怎麼用、看到什麼才算成功。
- ✅「打開網頁按開始，看得到主角，方向鍵能控制它吃東西」
- ❌「寫好 HTML 檔」（這只是動作，不是成功的樣子）

## 2. 選最簡單能做到的做法
一個檔案能完成就不要拆成很多檔；不要先裝一堆套件。

## 3. 先決定怎麼驗證 —— 跟使用者用它的方式一樣
- 程式／腳本：實際執行，看輸出對不對
- 網頁、遊戲、HTML 報告：用 `page_look` 打開，照使用者的操作做（按「開始」、按方向鍵…），看畫面和錯誤
- 服務／網站：打它的網址或 port，看到回應
驗證要排進計畫，是獨立的一步，不是最後順口一句「應該可以了」。

## 4. 做 → 驗證 → 不對就改 → 再驗證
驗證沒過就不能說完成。說完成時，講你怎麼驗證的、看到了什麼。

# 修 bug
1. **先重現**：照使用者描述的操作，親眼看到問題（網頁、遊戲用 `page_look`）。看不到問題就不要猜著改。
2. **找原因**：讀程式碼，對照看到的現象。用 python 模擬邏輯 ≠ 看到畫面 —— 畫面的問題（看不到、太淡、被蓋住、跑版）要看畫面才找得到。
3. **改檔案本身**：用 `edit_file` 只改要改的那幾行（新檔才用 write_file）。只寫測試／模擬腳本不算修；把整份檔案貼在回答裡也不算 —— 那不會存檔。
4. **用同樣的操作再看一次**：問題消失才算修好。看到的還是不對，就是還沒好 —— 不要找理由解釋掉（「可能還沒載入」「應該只是比較小」），繼續找下一個原因。
5. **回報**：原因是什麼、改了哪個檔的哪裡、怎麼確認修好的。
   檔案沒改、沒重新確認，就不可以說「已修復」。
